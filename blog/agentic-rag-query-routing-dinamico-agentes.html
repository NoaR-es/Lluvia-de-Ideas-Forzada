RAG en Dispositivos

En arquitecturas móviles y locales, enrutar consultas de forma inteligente ahorra ciclos de computación y batería de forma radical.

01 Evolución de Paradigma

1. El Límite del RAG Ingenuo (Naive RAG) y la Paradoja de la Similitud Coseno

El patrón inicial de RAG popularizado en 2023 consistía en un flujo lineal determinista: tomar la consulta del usuario, convertirla en un vector numérico mediante un modelo de embeddings, buscar los \( k \) fragmentos con menor distancia de coseno en una base vectorial e inyectarlos directamente en el prompt del sistema.

A septiembre de 2026, la experiencia en producción ha revelado que este enfoque lineal colapsa en tres escenarios fundamentales:

Similitud ≠ Relevancia

Dos textos pueden ser sintácticamente cercanos en el espacio latente pero aportar información irrelevante o desactualizada para la resolución del problema.

Consultas Multi-Dominio

Una pregunta como "¿Cómo impactan las limitaciones térmicas del chip X en la arquitectura de sincronización P2P?" requiere consultar dos fuentes de datos incompatibles.

Incapacidad de Fallback

Si la base vectorial no contiene información suficiente, el modelo responde utilizando fragmentos inútiles en lugar de reconocer el vacío de conocimiento.

02 Arquitectura Agéntica

2. Anatomía de Agentic RAG: El Agente como Investigador Activo

A diferencia del RAG pasivo, Agentic RAG convierte la recuperación de información en un bucle de deliberación autónomo. El modelo no recibe fragmentos obligados: el modelo dispone de herramientas de recuperación y toma decisiones reflexivas:

Las Cuatro Decisiones de un Agente de Recuperación:
  1. ¿Es necesaria la recuperación? Si la consulta es puramente lógica, matemática o conceptual, el agente responde directamente sin incurrir en latencia de búsqueda.
  2. ¿A qué índice o almacén acudir? Enrutamiento selectivo entre base de datos vectorial de proyectos, documentación estructurada o fuentes externas.
  3. ¿El contexto recuperado es suficiente? Evaluación crítica de fidelidad y cobertura antes de redactar la respuesta.
  4. ¿Se requiere reformulación? Si los resultados iniciales son pobres, reformular la consulta con sinónimos técnicos y reintentar.
03 Mecanismos de Selección

3. Estrategias de Query Routing Dinámico

El enrutamiento de consultas (Query Routing) es el cerebro clasificador que intercepta la intención del usuario o agente antes de cualquier operación costosa. En 2026 conviven tres técnicas principales:

A. Router Semántico Basado en Clasificadores Ligeros (Embeddings Router)

Calcula la similitud de la consulta con vectores prototipo de cada categoría. Tiene una latencia ultrabaja (menor a 5ms) y es ideal para ejecutarse on-device en teléfonos móviles sin consumir cuota de API.

B. Router Basado en Inferencia de Esquema (LLM Function Router)

El modelo examina el prompt y devuelve un JSON estructurado con el destino (ej. destination: "vector_store_ideas", search_type: "hybrid"). Ofrece máxima flexibilidad semántica a cambio de mayor latencia (150-300ms).

C. Router Híbrido Jerárquico

Un modelo local on-device resuelve las decisiones evidentes al instante, escalando únicamente consultas ambiguas al motor en la nube.

04 Consultas Complejas

4. Descomposición Multi-Hop y Planificación de Búsqueda

Cuando un dilema de diseño de producto o ingeniería involucra múltiples dependencias causales, una única consulta a la base de datos es incapaz de recuperar todo el cuadro.

La técnica Multi-Hop desglosa el requerimiento en un grafo acíclico de sub-consultas: la respuesta del primer salto (ejemplo: determinar el límite de memoria del modelo local) se convierte en parámetro de filtro para el segundo salto (buscar técnicas de cuantización compatibles en el repositorio técnico).

05 Código de Producción

5. Implementación Completa en Python 3.12+: Enrutador Dinámico Asíncrono

El siguiente script completo implementa un enrutador inteligente de consultas con validación de suficiencia y fallback determinista:

agentic_query_router.py Python 3.12+ / AsyncIO 
import asyncio
from typing import Literal, Dict, Any, List
from pydantic import BaseModel, Field

# 1. Esquema de Decisión de Enrutamiento
class RouteDecision(BaseModel):
    destination: Literal["vector_db_projects", "local_sqlite_room", "direct_reasoning"]
    reasoning: str = Field(..., description="Justificación técnica de la ruta")
    reformulated_query: str = Field(..., description="Query optimizada para el destino")

# 2. Clase de Enrutamiento Dinámico
class AgenticQueryRouter:
    async def route_query(self, query: str) -> RouteDecision:
        query_lower = query.lower()

        # Regla Heurística 1: Consultas sobre esquemas relacionales o estado de la app
        if any(k in query_lower for k in ["tabla", "ranking", "votos", "miembros"]):
            return RouteDecision(
                destination="local_sqlite_room",
                reasoning="La consulta requiere datos estructurados del estado local relacional.",
                reformulated_query=query
            )

        # Regla Heurística 2: Ideación conceptual abstracta
        if any(k in query_lower for k in ["lluvia de ideas", "disrupción", "scamper", "analogia"]):
            return RouteDecision(
                destination="vector_db_projects",
                reasoning="Requiere búsqueda semántica de conceptos en la base vectorial de proyectos.",
                reformulated_query=f"técnicas y conceptos afines a: {query}"
            )

        # Regla Heurística 3: Operaciones lógicas puras
        return RouteDecision(
            destination="direct_reasoning",
            reasoning="La consulta no requiere recuperación externa, se resuelve con inferencia pura.",
            reformulated_query=query
        )

    async def execute_pipeline(self, user_prompt: str) -> Dict[str, Any]:
        decision = await self.route_query(user_prompt)
        
        if decision.destination == "local_sqlite_room":
            result = f"[Room SQLite]: Consulta ejecutada sobre tablas locales con éxito."
        elif decision.destination == "vector_db_projects":
            result = f"[Base Vectorial]: Top-3 fragmentos semánticos recuperados para: '{decision.reformulated_query}'"
        else:
            result = f"[Inferencia Pura]: Respuesta generada directamente por el modelo."

        return {
            "prompt": user_prompt,
            "decision": decision.model_dump(),
            "result": result
        }

# Demostración en ejecución
if __name__ == "__main__":
    router = AgenticQueryRouter()
    queries = [
        "¿Cuáles son las ideas con más votos en el ranking de la sala?",
        "Buscar analogías biológicas para optimizar la caché",
        "Calcula la complejidad asintótica de un árbol B+"
    ]

    async def main():
        for q in queries:
            out = await router.execute_pipeline(q)
            print(f"Query:", out['prompt'])
            print(f"Destino:", out['decision']['destination'])
            print(f"Resultado:", out['result'])
            print("-" * 40)

    asyncio.run(main())
06 Autocorrección de Contexto

6. Corrective RAG (CRAG) y Bucles de Verificación Reflexiva

Incluso con un enrutador avanzado, los fragmentos devueltos por un almacén vectorial pueden contener ruido. El patrón Corrective RAG (CRAG) introduce un nodo evaluador que asigna un grado de confianza al conjunto de fragmentos:

Estado: Correct (Correcto)

El contexto es rico y directamente aplicable. Se envía a síntesis sin operaciones adicionales.

Estado: Ambiguous (Ambiguo)

El contexto es parcial. El agente combina los fragmentos con una búsqueda ampliada o pide aclaración al usuario.

Estado: Incorrect (Inadecuado)

El contexto no responde a la pregunta. Se descarta para evitar alucinaciones y se busca por canales alternativos.

07 Guía Operativa

7. Checklist para Producción en Septiembre de 2026

  • ✓ Enrutamiento en Capas: Utilizar routers heurísticos ultrarrápidos para consultas deterministas y reservar routers con LLMs únicamente para solicitudes ambiguas.
  • ✓ Descarte de Ruido en Tiempo Real: Aplicar un filtro de umbral de similitud (por ejemplo, coseno > 0.60) para evitar que fragmentos irrelevantes contaminen la ventana de contexto.
  • ✓ Persistencia Híbrida: Coexistencia limpia entre bases de datos relacionales estructuradas (como Room en Android o SQLite) para transacciones y bases vectoriales para similitud conceptual.

Del Almacén Pasivo al Agente de Conocimiento Activo

La madurez de las arquitecturas de inteligencia artificial en 2026 exige abandonar la búsqueda vectorial estática. Dotar a los agentes de la capacidad de evaluar sus propias lagunas de información y navegar inteligentemente entre múltiples motores es la base para construir herramientas de asistencia cognitiva verdaderamente útiles y seguras.
