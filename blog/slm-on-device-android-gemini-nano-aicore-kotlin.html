Puntos Clave de Arquitectura Android On-Device (2026)

  • ✓ AICore System Service (Gemini Nano): Cero consumo de RAM del espacio de usuario de tu aplicación, aceleración directa por NPU y pesos gestionados por el sistema operativo sin inflar el tamaño del APK.
  • ✓ Motor Nativo C++ (llama.cpp NDK): Máxima soberanía técnica para ejecutar GGUF personalizados (Llama 3.2 1B/3B, Gemma 2 2B) en cualquier dispositivo Android mediante bindings JNI optimizados con ARM NEON.
  • ✓ Streaming Reactivo Asíncrono: Implementación de corrutinas Kotlin con Flow<String> para renderizado progresivo token a token sin bloquear el hilo principal (Main Thread).
  • ✓ Persistencia Atómica en Room (SQLite): Almacenamiento local de ideas, metadatos de inferencia (latencia en ms, tokens/segundo) y vectores sin dependencias de red.

01. La Revolución de los Modelos On-Device en el Ecosistema Android (Septiembre 2026)

Durante los primeros años del auge de los modelos de lenguaje, el desarrollo en Android se limitó a crear clientes HTTP que enviaban peticiones a servidores remotos. Esta arquitectura, aunque sencilla de implementar, introduce tres problemas insalvables para aplicaciones profesionales y de privacidad crítica:

  1. Privacidad y Cumplimiento Normativo: Cualquier texto ingresado por el usuario viaja por internet, lo que imposibilita su uso en entornos corporativos confidenciales, notas privadas o sectores regulados (médico, legal, financiero).
  2. Costes de Operación Continuos: Cada sesión de brainstorming o ideación con agentes remotos acumula costes en tokens de API que escalan de forma lineal con el número de usuarios activos.
  3. Dependencia Absoluta de Conectividad: La aplicación queda inutilizada en aviones, zonas rurales o trenes subterráneos donde no existe cobertura estable de red.

En septiembre de 2026, la madurez del silicio móvil ha cambiado radicalmente las reglas del juego. Los procesadores modernos (Snapdragon 8 Gen 3/4, Google Tensor G4/G5 y MediaTek Dimensity 9300/9400) incorporan Unidades de Procesamiento Neuronal (NPUs) dedicadas capaces de entregar más de 45 TOPS en cálculos INT4 y FP16. Ejecutar un SLM de 2 a 3 mil millones de parámetros de forma local ya no es una demostración teórica; es una realidad de producción con velocidades que superan los 30 tokens por segundo.

02. Comparativa Arquitectónica: Google AICore vs Motor Nativo NDK

Al diseñar una arquitectura móvil Android para inferencia local, nos encontramos con dos caminos técnicos complementarios:

Criterio Técnico Vía A: Google AICore (Gemini Nano) Vía B: llama.cpp Nativo (NDK / JNI)
Ubicación del Modelo Partición del Sistema Operativo Android Almacenamiento interno de la App (o descarga a demanda)
Impacto en Memoria RAM 0 MB en la app (reside en el proceso de sistema AICore) 1.2 GB a 2.5 GB en el espacio de memoria nativo del proceso
Aceleración de Hardware NPU oficial optimizada por el fabricante (TPU/NPU) CPU multihilo (ARM NEON) o GPU Vulkan/OpenCL
Compatibilidad Dispositivos certificados (Pixel 8+, Galaxy S24+, etc.) Universal en cualquier Android ARM64 con 6GB+ RAM
Flexibilidad de Pesos Fija (Gemini Nano multimodal/texto) Total (Gemma 2, Phi-3.5, Llama 3.2, Qwen 2.5 en GGUF)

La estrategia más robusta para una aplicación de nivel industrial consiste en implementar un patrón Estrategia (Strategy Pattern) con un coordinador local: si el dispositivo cuenta con el servicio AICore activo y listo, se delega en Gemini Nano para obtener máxima velocidad y mínimo consumo energético; si el dispositivo carece de AICore o el usuario prefiere un modelo específico de código abierto, el sistema recurre al runtime nativo compilado en C++.

03. Implementación de Gemini Nano con Google AI Edge y AICore en Kotlin

Google AICore es un servicio del sistema que gestiona el ciclo de vida, descarga, actualización y ejecución de Gemini Nano. La aplicación cliente se comunica mediante llamadas IPC optimizadas a través del SDK oficial de Google AI Edge.

A continuación se presenta la implementación completa en Kotlin de GeminiNanoService.kt, utilizando corrutinas reactivas y flujos de datos (Flow) para emitir cada token de texto conforme es generado por el silicio:

GeminiNanoService.kt Kotlin 2.0 / Coroutines & Flow 
package es.noar.lluviaforzada.ai.local

import android.content.Context
import com.google.ai.edge.aicore.AICoreClient
import com.google.ai.edge.aicore.AICoreException
import com.google.ai.edge.aicore.GenerativeModel
import com.google.ai.edge.aicore.ModelStatus
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.channels.awaitClose
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.callbackFlow
import kotlinx.coroutines.flow.flowOn
import kotlinx.coroutines.withContext

/**
 * Servicio encargado de orquestar la inferencia en local mediante Google AICore (Gemini Nano).
 * Maneja el estado de disponibilidad del modelo en el sistema operativo y el streaming reactivo.
 */
class GeminiNanoService(private val context: Context) {

    private val aiCoreClient: AICoreClient by lazy {
        AICoreClient.create(context)
    }

    private var generativeModel: GenerativeModel? = null

    /**
     * Comprueba si Gemini Nano está disponible y preparado para inferencia en la NPU del dispositivo.
     */
    suspend fun checkModelAvailability(): ModelAvailabilityStatus = withContext(Dispatchers.IO) {
        try {
            val status: ModelStatus = aiCoreClient.getModelStatus("gemini-nano")
            when (status) {
                ModelStatus.AVAILABLE -> {
                    generativeModel = aiCoreClient.getGenerativeModel("gemini-nano")
                    ModelAvailabilityStatus.Ready
                }
                ModelStatus.DOWNLOADING -> ModelAvailabilityStatus.Downloading
                ModelStatus.DOWNLOADABLE -> ModelAvailabilityStatus.NeedsDownload
                ModelStatus.UNSUPPORTED_DEVICE -> ModelAvailabilityStatus.Unsupported
                else -> ModelAvailabilityStatus.Unavailable
            }
        } catch (e: AICoreException) {
            ModelAvailabilityStatus.Error(e.message ?: "Error desconocido al consultar AICore")
        }
    }

    /**
     * Solicita la descarga de los pesos de Gemini Nano a la partición protegida del sistema operativo.
     */
    suspend fun requestModelDownload(): Boolean = withContext(Dispatchers.IO) {
        try {
            aiCoreClient.downloadModel("gemini-nano")
            true
        } catch (e: Exception) {
            false
        }
    }

    /**
     * Ejecuta una consulta sobre Gemini Nano emitiendo los fragmentos generados a través de un Flow.
     *
     * @param systemPrompt Directiva del asistente o ideador (reglas de pensamiento lateral).
     * @param userPrompt Consulta o desafío creativo introducido por el usuario.
     */
    fun generateStreamingResponse(systemPrompt: String, userPrompt: String): Flow<String> = callbackFlow {
        val model = generativeModel ?: run {
            close(IllegalStateException("El modelo Gemini Nano no ha sido inicializado."))
            return@callbackFlow
        }

        val fullPrompt = "$systemPrompt\n\n[ENTRADA DE USUARIO]: $userPrompt\n[RESPUESTA]:"

        try {
            val streamResponse = model.generateContentStream(fullPrompt)
            for (chunk in streamResponse) {
                chunk.text?.let { textToken ->
                    trySend(textToken)
                }
            }
            channel.close()
        } catch (e: Exception) {
            close(e)
        }

        awaitClose {
            // Liberación de recursos del stream si el Flow es cancelado por el recolector
        }
    }.flowOn(Dispatchers.IO)
}

sealed class ModelAvailabilityStatus {
    object Ready : ModelAvailabilityStatus()
    object Downloading : ModelAvailabilityStatus()
    object NeedsDownload : ModelAvailabilityStatus()
    object Unsupported : ModelAvailabilityStatus()
    object Unavailable : ModelAvailabilityStatus()
    data class Error(val message: String) : ModelAvailabilityStatus()
}

04. Integración de llama.cpp Nativo mediante NDK y JNI en Kotlin

Cuando se requiere ejecutar modelos de pesos abiertos específicos (por ejemplo, Llama 3.2 1B/3B o Gemma 2 2B en formato GGUF con cuantización Q4_K_M), el motor oficial de la comunidad es llama.cpp. Para integrarlo en Android:

  1. Se compila llama.cpp con el Android NDK r27+ para la arquitectura arm64-v8a con soporte para instrucciones vectoriales ARM NEON y FP16.
  2. Se implementa una capa JNI en C++ que expone funciones nativas para inicializar el contexto (llama_init_from_file), configurar el tamaño de contexto KV-cache y decodificar tokens en un bucle continuo.
  3. Se consume desde Kotlin a través de métodos external gestionados en un hilo de trabajo en segundo plano.
LlamaCppNativeBridge.kt Kotlin JNI Native Bridge 
package es.noar.lluviaforzada.ai.local

import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.channels.awaitClose
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.callbackFlow
import kotlinx.coroutines.flow.flowOn
import java.io.File

/**
 * Enlace directo JNI con la biblioteca compilada libllamacpp_jni.so.
 * Permite ejecutar cualquier modelo cuantizado GGUF en la CPU/GPU del dispositivo móvil.
 */
class LlamaCppNativeBridge {

    companion object {
        init {
            System.loadLibrary("llamacpp_jni")
        }
    }

    private var nativeContextHandle: Long = 0L

    // Métodos nativos implementados en C++ JNI
    private external fun nativeInitModel(modelPath: String, nThreads: Int, nCtx: Int): Long
    private external fun nativeFreeModel(contextHandle: Long)
    private external fun nativeGenerate(
        contextHandle: Long,
        prompt: String,
        temperature: Float,
        topP: Float,
        callback: NativeTokenCallback
    )

    fun interface NativeTokenCallback {
        fun onToken(token: String): Boolean // Retornar false detiene la generación
    }

    /**
     * Carga el archivo GGUF en memoria nativa asignando los hilos de CPU óptimos.
     */
    fun loadModel(modelFile: File, contextSize: Int = 2048): Boolean {
        if (!modelFile.exists()) return false
        val availableCores = Runtime.getRuntime().availableProcessors()
        // Reservar 2 núcleos para la UI y servicios del sistema para evitar congelaciones
        val computeThreads = maxOf(1, availableCores - 2)
        nativeContextHandle = nativeInitModel(modelFile.absolutePath, computeThreads, contextSize)
        return nativeContextHandle != 0L
    }

    /**
     * Flujo reactivo que emite cada token decodificado por llama.cpp en tiempo real.
     */
    fun generateStream(prompt: String, temperature: Float = 0.7f, topP: Float = 0.9f): Flow<String> = callbackFlow {
        if (nativeContextHandle == 0L) {
            close(IllegalStateException("Modelo llama.cpp no cargado en memoria."))
            return@callbackFlow
        }

        nativeGenerate(
            nativeContextHandle,
            prompt,
            temperature,
            topP,
            NativeTokenCallback { token ->
                val sent = trySend(token).isSuccess
                sent // Si el canal se cerró o se canceló, retorna false y aborta C++
            }
        )
        channel.close()

        awaitClose {
            // Cancelación gestionada por el recolector de corrutinas
        }
    }.flowOn(Dispatchers.Default)

    /**
     * Libera la memoria RAM nativa reservada por los pesos y la KV-cache.
     */
    fun close() {
        if (nativeContextHandle != 0L) {
            nativeFreeModel(nativeContextHandle)
            nativeContextHandle = 0L
        }
    }
}

05. Persistencia Local Atómica y Auditoría con Room (SQLite)

Un modelo de lenguaje on-device necesita una base de datos local sólida que garantice que ninguna idea, rama de pensamiento o propuesta generada se pierda. En Android, Room (SQLite) proporciona la arquitectura ideal: integridad referencial, transaccionalidad ACID y observación reactiva mediante corrutinas.

Cada registro almacena no sólo el contenido de la idea generada, sino también los metadatos de auditoría de inferencia: motor utilizado (AICore vs llama.cpp), latencia hasta el primer token (TTFT) y tasa de generación en tokens por segundo:

IdeaLocalEntities.kt Room SQLite Architecture 
package es.noar.lluviaforzada.data.local

import androidx.room.Dao
import androidx.room.Database
import androidx.room.Entity
import androidx.room.Insert
import androidx.room.OnConflictStrategy
import androidx.room.PrimaryKey
import androidx.room.Query
import androidx.room.RoomDatabase
import kotlinx.coroutines.flow.Flow

/**
 * Entidad que representa una idea generada localmente por los motores de inferencia.
 */
@Entity(tableName = "ideas_generadas")
data class IdeaEntity(
    @PrimaryKey(autoGenerate = true)
    val id: Long = 0L,
    val projectId: Long,
    val topicId: Long,
    val title: String,
    val content: String,
    val classification: String, // 'SEMILLA' (Visión), 'BROTE' (En desarrollo), 'FRUTO' (Madura)
    val inferenceEngine: String, // 'GEMINI_NANO_AICORE' o 'LLAMACPP_NDK'
    val latencyMs: Long,
    val tokensPerSecond: Float,
    val timestamp: Long = System.currentTimeMillis()
)

@Dao
interface IdeaDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertIdea(idea: IdeaEntity): Long

    @Query("SELECT * FROM ideas_generadas WHERE topicId = :topicId ORDER BY timestamp DESC")
    fun getIdeasByTopicFlow(topicId: Long): Flow<List<IdeaEntity>>

    @Query("SELECT * FROM ideas_generadas WHERE projectId = :projectId ORDER BY timestamp DESC")
    suspend fun getIdeasByProject(projectId: Long): List<IdeaEntity>

    @Query("DELETE FROM ideas_generadas WHERE id = :ideaId")
    suspend fun deleteIdea(ideaId: Long): Int
}

@Database(entities = [IdeaEntity::class], version = 1, exportSchema = true)
abstract class AppDatabase : RoomDatabase() {
    abstract fun ideaDao(): IdeaDao
}

06. El Orquestador Local: Coordinador Unificado de Inferencia

Uniendo todas las piezas, implementamos el LocalInferenceCoordinator.kt. Este componente actúa como fachada única para la interfaz de usuario: evalúa el estado del hardware, selecciona el motor óptimo, mide las métricas de rendimiento y persiste automáticamente el resultado en Room:

LocalInferenceCoordinator.kt Kotlin / Mobile AI Orchestrator 
package es.noar.lluviaforzada.ai.local

import es.noar.lluviaforzada.data.local.IdeaDao
import es.noar.lluviaforzada.data.local.IdeaEntity
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.flow
import java.io.File

class LocalInferenceCoordinator(
    private val geminiNanoService: GeminiNanoService,
    private val llamaCppBridge: LlamaCppNativeBridge,
    private val ideaDao: IdeaDao
) {

    /**
     * Genera una idea innovadora aplicando pensamiento divergente, transmitiendo tokens
     * en tiempo real a la vista y registrando el resultado final en SQLite Room.
     */
    fun brainstormIdea(
        projectId: Long,
        topicId: Long,
        challengePrompt: String,
        fallbackGgufFile: File?
    ): Flow<InferenceProgress> = flow {
        val startTime = System.currentTimeMillis()
        var firstTokenTime: Long = 0L
        var totalTokens = 0
        val accumulatedText = StringBuilder()
        var engineUsed = "UNKNOWN"

        val systemDirective = """
            Eres un motor de ideación y pensamiento lateral on-device.
            Genera una solución no convencional al problema planteado.
            Estructura: [TÍTULO], [CONCEPTO DISRUPTIVO], [CATEGORÍA: SEMILLA|BROTE|FRUTO].
        """.trimIndent()

        // 1. Intentar inferencia primaria en Gemini Nano (AICore NPU)
        val aiCoreStatus = geminiNanoService.checkModelAvailability()
        if (aiCoreStatus is ModelAvailabilityStatus.Ready) {
            engineUsed = "GEMINI_NANO_AICORE"
            geminiNanoService.generateStreamingResponse(systemDirective, challengePrompt).collect { token ->
                if (totalTokens == 0) firstTokenTime = System.currentTimeMillis()
                totalTokens++
                accumulatedText.append(token)
                emit(InferenceProgress.Token(token, accumulatedText.toString()))
            }
        } else if (fallbackGgufFile != null && fallbackGgufFile.exists()) {
            // 2. Fallback a llama.cpp NDK si AICore no está disponible
            engineUsed = "LLAMACPP_NDK"
            val fullPrompt = "$systemDirective\n\nDesafío: $challengePrompt\nPropuesta:"
            llamaCppBridge.generateStream(fullPrompt).collect { token ->
                if (totalTokens == 0) firstTokenTime = System.currentTimeMillis()
                totalTokens++
                accumulatedText.append(token)
                emit(InferenceProgress.Token(token, accumulatedText.toString()))
            }
        } else {
            emit(InferenceProgress.Failure("No hay motores locales de inferencia disponibles en este dispositivo."))
            return@flow
        }

        val totalDurationMs = System.currentTimeMillis() - startTime
        val latencyFirstToken = if (firstTokenTime > 0) firstTokenTime - startTime else totalDurationMs
        val tokensPerSec = if (totalDurationMs > 0) (totalTokens.toFloat() / totalDurationMs) * 1000f else 0f

        // 3. Persistencia atómica en SQLite Room
        val savedId = ideaDao.insertIdea(
            IdeaEntity(
                projectId = projectId,
                topicId = topicId,
                title = "Idea Generada On-Device (${System.currentTimeMillis() % 10000})",
                content = accumulatedText.toString(),
                classification = "BROTE",
                inferenceEngine = engineUsed,
                latencyMs = latencyFirstToken,
                tokensPerSecond = tokensPerSec
            )
        )

        emit(
            InferenceProgress.Completed(
                ideaId = savedId,
                fullContent = accumulatedText.toString(),
                engine = engineUsed,
                latencyMs = latencyFirstToken,
                tokensPerSec = tokensPerSec
            )
        )
    }
}

sealed class InferenceProgress {
    data class Token(val chunk: String, val fullSoFar: String) : InferenceProgress()
    data class Completed(
        val ideaId: Long,
        val fullContent: String,
        val engine: String,
        val latencyMs: Long,
        val tokensPerSec: Float
    ) : InferenceProgress()
    data class Failure(val errorMessage: String) : InferenceProgress()
}

Preguntas Frecuentes sobre SLMs On-Device en Android

¿Gemini Nano aumenta el peso final del archivo APK? ▼

No. Los pesos del modelo Gemini Nano son descargados y gestionados de forma centralizada por el servicio de sistema Google AICore en una partición protegida del sistema operativo Android. El tamaño del APK sólo aumenta unos pocos kilobytes correspondientes a la biblioteca cliente de enlace.

¿Qué versión mínima de Android se requiere para ejecutar AICore en 2026? ▼

Google AICore está disponible en Android 14 y versiones superiores (Android 15 y 16) en dispositivos certificados con silicio compatible con NPU (Pixel 8 en adelante, Samsung Galaxy S24/S25, Xiaomi 14/15, etc.).

¿Es posible utilizar SQLite Room para guardar embeddings vectoriales? ▼

Sí. Los vectores se serializan típicamente como campos binarios BLOB (arrays de Float32 o Float16) o se vinculan mediante extensiones C++ de SQLite como sqlite-vec compiladas con el NDK de Android, permitiendo búsquedas por similitud de coseno directas en SQLite.
